# 任务清单 CLI 设计文档

## 1. 目标与边界

本工具提供一个最小化的本地任务清单命令行接口，支持：

- 新增任务；
- 按任务 `id` 升序列出全部任务；
- 将指定任务标记为完成；
- 将数据持久化至程序同目录下的 `todos.json`，以便重启后恢复。

实现仅使用运行时/标准库能力，不引入第三方依赖。任务不支持删除、编辑、分类或多用户并发协作；这些能力不在本期范围内。

## 2. 数据模型与持久化

### 2.1 单条任务

每条任务在内存和 JSON 文件中均使用以下结构：

```json
{
  "id": 1,
  "title": "购买牛奶",
  "completed": false
}
```

字段约束：

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| `id` | 整数 | 正整数、唯一、不可变 | 任务标识符 |
| `title` | 字符串 | 去除首尾空白后不得为空 | 任务标题 |
| `completed` | 布尔值 | `true` 或 `false` | 是否完成 |

### 2.2 文件格式

数据文件固定为程序同目录的 `todos.json`。文件根节点为任务数组：

```json
[
  {"id": 1, "title": "购买牛奶", "completed": false},
  {"id": 2, "title": "提交报告", "completed": true}
]
```

约定如下：

1. 文件不存在时，将其视为没有任务；首次成功新增任务时创建文件。
2. 每次会修改数据的命令（`add`、首次执行的 `done`）成功后，将完整任务数组写回文件。
3. 读取后应按 `id` 升序处理和展示；文件中原有顺序不作为业务顺序。
4. 新任务的 `id` 取现有任务最大 `id + 1`；空列表从 `1` 开始。任务被删除不在本期范围内，因此 `id` 不复用。
5. 写入使用 UTF-8 编码，并输出合法 JSON。可采用“先写临时文件、再替换原文件”的方式减少写入中断导致的数据损坏风险。

## 3. 命令格式

假设可执行程序名为 `todo`。命令中的 `<...>` 是必填参数，`[...]` 是可选参数。

### 3.1 新增任务

```text
todo add <标题>
```

- `<标题>` 由命令中 `add` 之后的全部参数按空格连接而成，因此可直接输入包含空格的标题。
- 程序去除标题首尾空白后保存。
- 成功时创建一条 `completed: false` 的任务，分配新 `id`，并持久化。

示例：

```text
$ todo add 购买 牛奶
Added: [1] 购买 牛奶
```

### 3.2 列出任务

```text
todo list
```

- 不接受额外参数。
- 从 `todos.json` 读取任务，按 `id` 升序输出。
- 每行输出一个任务，使用 `[x]` 表示已完成、`[ ]` 表示未完成：

```text
$ todo list
[ ] 1 购买牛奶
[x] 2 提交报告
```

- 没有任务时正常结束并输出：

```text
No tasks.
```

### 3.3 标记完成

```text
todo done <id>
```

- `<id>` 必须是一个正整数，且命令不能带有额外参数。
- 找到对应任务后，将其 `completed` 设为 `true` 并持久化。
- 如果任务已经完成，操作保持幂等：不改变其余数据，仍以成功结果返回。

示例：

```text
$ todo done 1
Completed: [1] 购买牛奶
```

### 3.4 帮助

当没有提供命令或提供 `help`、`--help`、`-h` 时，输出用法摘要：

```text
Usage:
  todo add <title>
  todo list
  todo done <id>
```

## 4. 处理流程

1. 解析命令名与参数，并先校验命令格式。
2. 对 `list`、`add`、`done` 读取 `todos.json`；文件不存在则使用空数组。
3. 校验读取出的数据满足任务模型约束（数组、字段完整、`id` 唯一且为正整数、标题非空、完成状态为布尔值）。
4. 执行对应业务操作。`list` 仅输出；`add` 和有效的 `done` 更新内存数据后写回文件。
5. 成功信息输出至标准输出；任何失败信息输出至标准错误，并返回非零退出码。

## 5. 错误处理

### 5.1 参数与命令错误

| 场景 | 处理 | 退出码 |
| --- | --- | --- |
| 未提供命令 | 输出帮助 | 0 |
| 未知命令 | 标准错误输出 `Error: unknown command: <command>`，随后输出用法 | 非 0 |
| `add` 缺少标题或标题仅含空白 | 标准错误输出 `Error: title is required` | 非 0 |
| `list` 带额外参数 | 标准错误输出 `Error: list does not accept arguments` | 非 0 |
| `done` 缺少、含多个或非整数的 id | 标准错误输出 `Error: id must be a positive integer` | 非 0 |
| `done` 的 id 小于等于 0 | 标准错误输出 `Error: id must be a positive integer` | 非 0 |
| 指定 id 不存在 | 标准错误输出 `Error: task <id> not found` | 非 0 |

### 5.2 数据与文件错误

| 场景 | 处理 | 退出码 |
| --- | --- | --- |
| `todos.json` 不存在 | 作为空任务列表继续执行 | 0（若后续操作成功） |
| 文件无法读取 | 标准错误输出 `Error: cannot read todos.json: <原因>`，不继续执行 | 非 0 |
| JSON 语法无效 | 标准错误输出 `Error: invalid todos.json: malformed JSON`，不覆盖原文件 | 非 0 |
| JSON 内容不符合数据模型 | 标准错误输出 `Error: invalid todos.json: invalid task data`，不覆盖原文件 | 非 0 |
| 无法创建目录、写入、替换或关闭数据文件 | 标准错误输出 `Error: cannot write todos.json: <原因>`；报告失败，避免显示成功信息 | 非 0 |

对于文件错误，`<原因>` 应来自底层系统错误的可读描述，但不应输出调用栈。发生读取、解析或校验失败时，程序不得尝试自动修复或覆盖现有文件，避免丢失用户数据。

## 6. 验收检查建议

- 连续执行两次 `add`，确认 `id` 分别为 1、2，且新增任务默认为未完成。
- 执行 `list`，确认任务按 `id` 升序输出、完成状态符号正确。
- 执行 `done 1` 后重新运行程序并 `list`，确认任务仍为完成状态。
- 对空标题、非法/不存在的 `id`、未知命令和带额外参数的 `list`，确认命令失败且不会改写数据。
- 分别使用不存在、格式损坏和结构不合法的 `todos.json`，确认行为符合错误处理约定。
