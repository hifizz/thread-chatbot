# 任务清单 CLI 设计

## 1. 目标与范围

本工具是一个无第三方依赖的本地任务清单命令行程序，支持：

- 新增任务；
- 按 `id` 升序列出全部任务；
- 将指定任务标记为完成；
- 将数据持久化到程序所在目录的 `todos.json`，使重启后数据不丢失。

本期不包含删除、修改标题、筛选任务、多用户或并发编辑能力。

## 2. 数据模型与持久化

### 2.1 任务模型

每个任务为一个 JSON 对象，字段如下：

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| `id` | 整数 | 正整数；在任务集合内唯一 | 任务标识 |
| `title` | 字符串 | 去除首尾空白后不能为空 | 任务标题 |
| `completed` | 布尔值 | `true` 或 `false` | 是否已完成 |

新增任务的 `completed` 固定为 `false`。

### 2.2 `todos.json` 文件格式

数据文件位于可执行程序（或主脚本）所在的同一目录，文件名固定为 `todos.json`。文件根节点是任务数组；空清单表示为 `[]`：

```json
[
  {
    "id": 1,
    "title": "购买牛奶",
    "completed": false
  },
  {
    "id": 2,
    "title": "提交报告",
    "completed": true
  }
]
```

首次运行时，如 `todos.json` 不存在，程序将其视为空数组。每次成功执行新增或完成操作后，程序将完整任务数组写回该文件。建议写入格式化 JSON（例如两空格缩进）以便人工检查。

### 2.3 ID 分配与排序

- 新增时，`id` 取当前所有任务中最大 `id` 加 1；空清单的首个 `id` 为 1。
- ID 一经分配不复用。
- `list` 命令无论文件中的原始顺序如何，均按数值 `id` 升序输出。

## 3. 命令格式

以下以可执行命令名 `todo` 为例；实际入口名称可替换，但参数语义保持一致。

### 3.1 新增任务

```text
todo add <标题>
```

`<标题>` 为命令行中 `add` 后的全部参数文本，可包含空格；调用方应使用引号包裹含空格的标题。例如：

```text
todo add "购买牛奶"
```

成功后写入数据文件，并输出新增任务的信息，例如：

```text
Added #1: 购买牛奶
```

### 3.2 列出任务

```text
todo list
```

输出所有任务，每个任务一行，按 ID 升序。例如：

```text
[ ] 1 购买牛奶
[x] 2 提交报告
```

其中 `[ ]` 表示未完成，`[x]` 表示已完成。没有任务时输出明确提示：

```text
No tasks.
```

### 3.3 标记完成

```text
todo done <id>
```

`<id>` 必须是十进制正整数。例如：

```text
todo done 1
```

成功时将该任务的 `completed` 更新为 `true` 并持久化，输出：

```text
Completed #1: 购买牛奶
```

对已完成任务再次执行 `done` 是幂等操作：命令仍成功，状态保持 `true`，并可输出相同的完成确认信息。

### 3.4 帮助

无参数、`help` 或 `--help` 时输出简要用法：

```text
Usage:
  todo add <title>
  todo list
  todo done <id>
```

## 4. 处理流程

1. 解析命令及参数。
2. 对 `list`、`add`、`done` 读取 `todos.json`；文件不存在时创建内存中的空清单。
3. 校验读取的数据和命令参数。
4. 执行对应操作：列出、追加任务或更新完成状态。
5. 对会修改数据的操作，将更新后的完整清单写回 `todos.json`；仅在写入成功后报告成功。

## 5. 错误处理

错误信息输出到标准错误；发生错误时返回非零退出码。正常完成返回 0。实现不依赖第三方库，使用语言标准库完成参数解析与 JSON 读写。

| 场景 | 判定 | 行为与示例错误信息 |
| --- | --- | --- |
| 未知命令 | 子命令不是 `add`、`list`、`done`、`help` 或 `--help` | 不修改文件，输出 `Error: unknown command '<command>'.`，随后显示用法 |
| `add` 缺少标题 | `add` 后无参数 | 不修改文件，输出 `Error: title is required.` |
| 空白标题 | 标题拼接并去除首尾空白后为空 | 不修改文件，输出 `Error: title must not be empty.` |
| `list` 参数错误 | `list` 后还有额外参数 | 不修改文件，输出 `Error: list takes no arguments.` |
| `done` 缺少或多出参数 | 参数数量不等于 1 | 不修改文件，输出 `Error: usage: todo done <id>.` |
| 非法 ID | `id` 不是正整数（如 `0`、`-1`、`abc`） | 不修改文件，输出 `Error: id must be a positive integer.` |
| 任务不存在 | 清单中没有指定 ID | 不修改文件，输出 `Error: task #<id> not found.` |
| 数据文件不是合法 JSON | JSON 解析失败 | 不覆盖原文件，输出 `Error: cannot read todos.json: invalid JSON.` |
| 数据文件结构无效 | 根节点不是数组，或任务缺字段、字段类型错误、ID 非唯一/非正 | 不覆盖原文件，输出 `Error: cannot read todos.json: invalid task data.` |
| 读取失败 | 权限、I/O 等导致无法读取已有文件 | 不修改文件，输出 `Error: cannot read todos.json: <系统错误>.` |
| 写入失败 | 权限、磁盘空间、I/O 等导致无法保存 | 报告失败且不输出成功信息，输出 `Error: cannot write todos.json: <系统错误>.` |

对于写入失败，实现应尽可能避免破坏已有文件：可先写入同目录临时文件，再通过原子替换更新 `todos.json`；若运行环境无法保证原子替换，至少应确保写入错误被检测并返回失败。

## 6. 验证要点

- 在无 `todos.json` 的目录执行 `todo add "任务 A"`，应创建文件且任务 ID 为 1、完成状态为 `false`。
- 连续新增多个任务后，`todo list` 应始终按数值 ID 升序展示。
- 执行 `todo done 1` 后，重启程序并执行 `todo list`，任务 1 应显示为完成。
- 对错误命令、空标题、非法/不存在的 ID，以及损坏的 `todos.json`，应返回非零状态且不改写有效数据。
