# 任务清单 CLI 设计文档

## 1. 目标与范围

实现一个无第三方依赖的最小任务清单命令行工具。工具支持新增任务、列出任务及将任务标记为完成；所有数据持久化到程序同目录下的 `todos.json`，因此进程退出或重启后任务仍可用。

本设计只定义单一任务清单，不包含删除、编辑、优先级、分类、多用户或并发协作等功能。

## 2. 数据模型与持久化

### 2.1 任务模型

每个任务使用以下字段：

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | 整数 | 正整数、全局唯一，用于引用任务。新增时由程序生成。 |
| `title` | 字符串 | 任务标题；去除首尾空白后必须非空。 |
| `completed` | 布尔值 | `false` 表示未完成，`true` 表示已完成。 |

新增任务的初始状态必须为 `completed: false`。任务完成后仅将该字段更新为 `true`，保留原有 `id` 和标题。

### 2.2 文件格式

数据文件固定为可执行程序所在目录的 `todos.json`。文件内容为 UTF-8 编码的 JSON 数组，例如：

```json
[
  {"id": 1, "title": "购买牛奶", "completed": false},
  {"id": 2, "title": "提交报告", "completed": true}
]
```

空任务清单表示为：

```json
[]
```

首次运行时若 `todos.json` 不存在，程序将其视为空清单；在第一次成功写入时创建该文件。

### 2.3 ID 分配与读写规则

- 新任务的 `id` 为当前任务中最大 `id + 1`；空清单从 `1` 开始。
- 不复用已经消失的 ID，以减少引用歧义。
- 每个命令执行时先从文件读取最新数据；发生修改后将完整任务数组写回 `todos.json`。
- 列表输出必须按 `id` 数值升序排序，不依赖 JSON 数组当前排列顺序。
- 写入前应完成内存中的校验和修改；写入失败时命令返回错误，不应报告操作成功。

## 3. 命令格式

以下以可执行程序名 `todo` 为例。命令不依赖第三方库；参数解析可使用目标语言标准库或自行实现。

### 3.1 总览

```text
todo add <标题>
todo list
todo complete <id>
todo help
```

`help` 可选实现；无参数时也应输出简明用法并以非零状态退出。标题由 `add` 后的剩余参数以空格连接而成，因此包含空格的标题可直接输入，也可使用 shell 引号保留特殊字符。

### 3.2 新增任务：`add`

```text
todo add <标题>
```

示例：

```text
todo add 购买牛奶
todo add "完成月度报告"
```

处理流程：

1. 读取并校验现有任务数据。
2. 校验标题在去除首尾空白后非空。
3. 分配下一个 ID，创建未完成任务。
4. 持久化整个任务列表。
5. 在标准输出确认创建结果，例如：`已添加任务 3：购买牛奶`。

成功退出码为 `0`。

### 3.3 列出任务：`list`

```text
todo list
```

读取任务后，按 `id` 升序逐行输出。建议稳定、便于脚本和人工阅读的格式为：

```text
[ ] 1 购买牛奶
[x] 2 提交报告
```

其中 `[ ]` 表示未完成，`[x]` 表示已完成。空清单时输出 `暂无任务`。该命令不修改数据，成功退出码为 `0`。

### 3.4 完成任务：`complete`

```text
todo complete <id>
```

示例：

```text
todo complete 2
```

`id` 必须是十进制正整数，且必须匹配已有任务。匹配后将任务的 `completed` 设为 `true` 并写回文件，成功时可输出：

```text
任务 2 已完成
```

对已经完成的任务重复执行本命令是幂等操作：保持 `completed: true`，仍以成功退出码 `0` 返回，并可提示该任务已处于完成状态。

## 4. 错误处理

### 4.1 通用约定

- 所有错误信息输出到标准错误流（stderr）；成功结果输出到标准输出（stdout）。
- 命令参数、数据内容、读写或 JSON 解析失败时退出码为非零（建议统一为 `1`）。
- 错误信息应说明可操作原因，但不输出堆栈或内部实现细节。
- 出错时不得写入部分或未经校验的数据；原有的有效 `todos.json` 应保持可恢复使用。

### 4.2 错误场景

| 场景 | 处理方式与示例信息 |
| --- | --- |
| 未提供命令或命令未知 | 输出用法，例如：`用法：todo <add|list|complete> ...`；非零退出。 |
| `add` 缺少标题或标题仅为空白 | 拒绝创建，输出：`错误：任务标题不能为空`。 |
| `list`、`add`、`complete` 接收到不应有的参数 | 拒绝执行并输出对应命令的用法。 |
| `complete` 缺少 ID | 输出：`错误：请提供任务 ID`。 |
| ID 不是正整数（含零、负数、小数或非数字） | 输出：`错误：任务 ID 必须是正整数`。 |
| ID 不存在 | 不写文件，输出：`错误：未找到任务 <id>`。 |
| `todos.json` 不存在 | 按空清单处理，不视为错误。 |
| 文件无法读取、权限不足或路径不是可读文件 | 输出：`错误：无法读取 todos.json：<原因>`。 |
| JSON 格式非法 | 拒绝继续操作，输出：`错误：todos.json 格式无效`。 |
| JSON 根节点不是数组，或任务缺字段、字段类型错误、ID 不唯一/非正数、标题为空 | 视为损坏数据并拒绝执行，输出：`错误：todos.json 数据结构无效`。 |
| 保存文件失败（例如无写权限或磁盘空间不足） | 输出：`错误：无法保存 todos.json：<原因>`；命令以非零状态结束。 |

## 5. 验证要点

实现完成后至少验证以下流程：

1. 在不存在 `todos.json` 的目录执行两次 `add`，确认生成 ID `1`、`2` 且初始状态均为未完成。
2. 执行 `list`，确认按 ID 升序输出及状态标识正确。
3. 执行 `complete 1` 后重新运行程序并执行 `list`，确认任务 `1` 状态仍为完成。
4. 对空标题、非法 ID、未知 ID、未知命令及损坏的 JSON 文件分别执行命令，确认返回非零退出码、错误在 stderr 且不破坏已有数据。
5. 在无第三方依赖的环境中运行上述命令，确认工具仅使用语言运行时或标准库。
