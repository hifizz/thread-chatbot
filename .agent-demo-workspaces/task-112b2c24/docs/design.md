# 任务清单 CLI 设计文档

## 1. 目标与范围

本工具是一个不依赖第三方库的最小任务清单命令行程序。它提供新增任务、列出任务、标记任务完成三项能力，并将数据持久化到程序所在目录的 `todos.json`，以保证进程重启后任务不会丢失。

本设计不包含任务删除、修改标题、分类、优先级、用户账户或并发协作等能力。

## 2. 数据模型

### 2.1 任务对象

每个任务使用一个 JSON 对象表示：

```json
{
  "id": 1,
  "title": "购买牛奶",
  "completed": false
}
```

字段约束：

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| `id` | 整数 | 正整数；在任务清单内唯一 | 任务标识符 |
| `title` | 字符串 | 去除首尾空白后不能为空 | 任务标题 |
| `completed` | 布尔值 | 必须为 `true` 或 `false` | 是否已完成 |

### 2.2 存储格式

程序在可执行程序（或主脚本）同目录读写 `todos.json`。文件根节点为任务数组：

```json
[
  {
    "id": 1,
    "title": "购买牛奶",
    "completed": false
  },
  {
    "id": 2,
    "title": "提交报告",
    "completed": true
  }
]
```

- 当 `todos.json` 不存在时，将其视为空清单，不应因此阻止 `add` 或 `list`。
- 新增任务的 `id` 为当前清单中最大 `id + 1`；空清单的首个任务 `id` 为 `1`。已完成任务不改变其 `id`。
- 每次会改变数据的命令（`add`、`complete`）仅在内存校验成功后，整体写回 JSON 文件，避免写出半条任务记录。
- 输出 JSON 时采用 UTF-8 编码及格式化缩进，便于人工检查。

## 3. 命令格式

假定程序入口名为 `todo`；实际实现可按所选语言的启动方式替换入口，但子命令与参数语义保持一致。

### 3.1 新增任务

```text
todo add <标题>
```

示例：

```text
todo add 购买牛奶
todo add "准备周会材料"
```

处理流程：

1. 将 `add` 之后的参数合并为标题；带空格的标题可用引号传入。
2. 去除标题首尾空白并校验非空。
3. 生成下一个唯一正整数 `id`，创建 `completed: false` 的任务。
4. 保存到 `todos.json`。
5. 在标准输出显示新增任务，例如：`已添加 [1] 购买牛奶`。

### 3.2 列出任务

```text
todo list
```

从 `todos.json` 加载全部任务，并按 `id` 升序输出。每行一个任务，推荐格式为：

```text
[1] [ ] 购买牛奶
[2] [x] 提交报告
```

其中 `[ ]` 表示未完成，`[x]` 表示已完成。没有任务时输出 `暂无任务`，并以成功状态退出。

### 3.3 标记完成

```text
todo complete <id>
```

示例：

```text
todo complete 2
```

处理流程：

1. 校验 `<id>` 是正整数。
2. 载入任务并按 `id` 查找。
3. 找到任务后将 `completed` 设置为 `true`，再保存文件。
4. 输出确认信息，例如：`已完成 [2] 提交报告`。

如果任务本来已经完成，命令仍可成功：保持数据不变并输出 `任务 [2] 已完成`。这使重复执行该命令具有幂等性。

### 3.4 帮助与未知命令

```text
todo help
todo --help
todo -h
```

帮助文本应列出 `add`、`list`、`complete` 的用法。未提供子命令或传入未知子命令时，也应在标准错误输出简短错误及用法提示。

## 4. 错误处理

### 4.1 参数与用户输入错误

下列错误属于用户可修正的输入问题：

| 场景 | 标准错误示例 | 退出码 |
| --- | --- | --- |
| 未提供命令或命令未知 | `错误：未知命令：remove`，随后显示用法 | `2` |
| `add` 未提供标题或标题全为空白 | `错误：任务标题不能为空` | `2` |
| `complete` 缺少 id | `错误：complete 需要一个任务 id` | `2` |
| id 不是正整数（如 `0`、`-1`、`abc`） | `错误：任务 id 必须是正整数` | `2` |
| id 不存在 | `错误：未找到任务 [42]` | `2` |
| 子命令参数数量不符合要求 | `错误：命令参数无效`，随后显示对应命令用法 | `2` |

错误信息输出到标准错误；成功结果输出到标准输出。

### 4.2 存储与数据错误

程序加载文件时必须验证根节点是数组，且每个元素均含有满足数据模型约束的 `id`、`title`、`completed` 字段；同时验证 `id` 不重复。发现异常时不得继续执行可能覆盖原文件的操作。

| 场景 | 处理方式 | 退出码 |
| --- | --- | --- |
| `todos.json` 不存在 | 按空清单处理 | `0`（若命令其余部分成功） |
| 文件无法读取或权限不足 | 输出 `错误：无法读取任务数据：<原因>` | `1` |
| JSON 语法无效 | 输出 `错误：任务数据格式无效，请检查 todos.json` | `1` |
| JSON 结构或字段校验失败 | 输出同上，不写回文件 | `1` |
| 写入失败、目录不可写或磁盘错误 | 输出 `错误：无法保存任务数据：<原因>` | `1` |

实现应捕获文件 I/O 与 JSON 解析异常，将其转换为上述面向用户的消息；错误详情可在消息中的 `<原因>` 位置提供简短系统原因，但不输出堆栈。写入可采用“先写临时文件、成功后替换目标文件”的方式进一步降低写入中断损坏原文件的风险。

## 5. 实现边界

- 仅使用目标语言标准库完成参数解析、JSON 序列化和文件读写。
- 每次命令执行均从磁盘重新加载数据；保存后即结束进程。
- 规格未要求多进程并发写入。若后续支持并发访问，应增加文件锁或冲突检测，避免两个进程基于同一旧版本覆盖彼此修改。
