## ADDED Requirements

### Requirement: 独立后台框架
系统 SHALL 提供 sidebar-08 风格的 `/admin` 外壳与静态样板页，导航和业务内容分离。

#### Scenario: 管理员打开后台
- **WHEN** 管理员访问 `/admin`
- **THEN** 显示侧边栏、页头、面包屑、账号菜单及明确标记为示例的内容区域

#### Scenario: 小屏导航
- **WHEN** 管理员在手机打开后台
- **THEN** 可打开导航抽屉并选择页面，页面不会撑宽视口

### Requirement: 服务端管理员角色
系统 SHALL 在独立成员表中保存管理员身份，服务端检查登录及成员资格，不信任客户端声明。

#### Scenario: 未登录
- **WHEN** 未登录用户打开 `/admin`
- **THEN** 跳转登录页并保留后台回跳地址

#### Scenario: 普通账号
- **WHEN** 普通账号访问后台或在注册时自行声明 admin 角色
- **THEN** 无法获得管理员权限，后台内容不显示

#### Scenario: 授权与撤销
- **WHEN** 维护者为已注册邮箱执行授权脚本
- **THEN** 创建唯一成员记录，重复执行不会重复授权，不存在的邮箱不会自动注册

#### Scenario: 撤销生效
- **WHEN** 成员记录被删除后用户重新访问后台
- **THEN** 服务端拒绝访问，不继续信任已打开页面的状态

### Requirement: 有限范围与发布门禁
本次 SHALL 仅新增后台骨架、样板页和管理员基础，不改变聊天与模型配置行为。

#### Scenario: 独立提交
- **WHEN** 比较新分支与 admin 目标分支
- **THEN** 不包含动态模型目录、缓存、聊天流程和正式 migration 的变更

#### Scenario: 发布
- **WHEN** 准备部署本功能
- **THEN** 先由 develop 集成任务生成并验证正式数据库迁移，再部署和授权已有账号
