## ADDED Requirements

### Requirement: 生成期间必须展示搜索活动
Thread Chat MUST 展示有明确边界且属于 Web Search 工具的活动状态，包括开始、查询词、完成、结果数和失败状态，同时不得暴露凭据或原始 provider payload。同一个 assistant 回答中的多次内部 Web Search 工具调用必须聚合为一个消息级活动；聚合终态必须优先采用已接受的来源，不得被后续遭拒绝的重复调用覆盖。聚合活动必须插入该回答第一次出现 Web Search 流事件的位置，不得固定在正文顶部或底部。

#### Scenario: 搜索开始
- **WHEN** 流接收到已通过校验的 Web Search 输入事件
- **THEN** 当前 assistant 回答使用静态图标和文字 shimmer 表示正在搜索，并展示查询词；图标本身不得闪烁

#### Scenario: 搜索完成
- **WHEN** 搜索工具结果到达
- **THEN** 活动面板显示搜索已完成及已接受的信息源数量

#### Scenario: 后续冗余调用遭到拒绝
- **WHEN** assistant 回答已经获得可用信息源，后续 Web Search 工具调用因预算耗尽或输入无效而遭到拒绝
- **THEN** 用户只看到一个成功的聚合活动，其中的信息源已经按 URL 去重，不得再看到与之矛盾的失败卡片

#### Scenario: 正文开始流式输出后才发起搜索
- **WHEN** 同一个 assistant 回答的首个 Web Search 事件之前已经出现正文 delta
- **THEN** 客户端先 flush 已缓冲的正文 delta，再将唯一的聚合活动插入前后正文之间

#### Scenario: 收到未知工具事件
- **WHEN** 流接收到不受支持或格式错误的工具事件
- **THEN** 消费器忽略该事件，不得创建虚假的搜索状态，也不得中断正文流式输出

#### Scenario: 搜索标签超过可用宽度
- **WHEN** 查询词或信息源标题长于搜索活动容器
- **THEN** 卡片必须保持在父容器内，查询词需要截断，每个信息源需要渲染成紧凑的发布者短名胶囊，并在面板下方保留 `mb-6` 间距

### Requirement: 基于联网结果的时效性声明必须引用真实搜索结果
回答依赖 Web Search 时，每项重要的时效性声明或经过外部核验的声明都 MUST 链接到本次回答的搜索工具实际返回的 URL。assistant 不得把搜索工具未返回的 URL 表述成已检索的信息源。

#### Scenario: 回答使用版本发布说明
- **WHEN** 某项结论依赖 Web Search 返回的版本发布说明
- **THEN** 该结论包含指向这条实际返回 URL 的 Markdown 链接

#### Scenario: 信息源相互冲突或证据不足
- **WHEN** 返回的信息源彼此不一致，或无法支持确定性结论
- **THEN** 回答必须说明不确定性，不得虚构共识

#### Scenario: 回答已经包含可信信息源链接
- **WHEN** 模型输出包含至少一个由本次回答搜索工具返回的 URL
- **THEN** 可信外部链接渲染成紧凑的信息源胶囊，并且服务端不得追加重复的 `信息源` footer
- **AND WHEN** 回答不包含任何可信信息源链接
- **THEN** 服务端使用紧凑标签追加一行兜底信息源

### Requirement: 搜索过程状态与最终回答必须采用不同的持久化策略
临时的 `starting` 和 `searching` 进度 MUST NOT 写入 branch tree。终态的 `completed` 和 `failed` 聚合活动、首个搜索事件对应的正文 offset，以及包含信息源链接和限制说明的最终 assistant 正文，都必须正常持久化并能在刷新后恢复。

#### Scenario: 刷新包含联网回答的对话树
- **WHEN** 用户刷新包含已完成联网回答的对话树
- **THEN** 终态聚合活动与回答正文、信息源链接一起保留，并继续显示在原始流顺序位置
- **AND** 过期的搜索进行中状态不得重新出现

#### Scenario: 搜索被中止
- **WHEN** 用户在搜索期间停止生成
- **THEN** 已完成的 assistant 正文和已经进入终态的搜索尝试按照现有停止行为保留
- **AND** 不得持久化任何“正在搜索”状态
