## Context

见 [proposal.md](proposal.md) 的动机。当前标题路由以 MiniMax 生成标题，并采用 AI SDK 的默认两次重试；标题结果失败时只保留组件实例内的 Set，因此刷新页面会丢失防重信息。该路由也在提示词和清洗阶段把标题限制为 4–8 个中文字符。

分支树作为完整 JSON 保存，新增可选字段可兼容历史状态而无需数据库迁移。项目已具备火山方舟 Coding Plan 的 OpenAI-compatible provider 与服务端密钥配置。

## Goals / Non-Goals

**Goals:**

- 使用 Coding Plan 中适合短文本的轻量模型生成分支标题。
- 让模型调用在配额、鉴权等确定性错误下只发生一次。
- 将自动尝试状态跨刷新持久化，并覆盖浏览器写入尚未完成的刷新窗口。
- 完整保存标题，把视觉截断限定在前端布局层。

**Non-Goals:**

- 不为现有分支提供自动或手动的再次生成入口。
- 不调整用户重命名的树级 `custom_title` 规则。
- 不为标题请求引入流式协议、工具调用或新的模型 SDK。
- 不承诺跨浏览器标签页的首次并发调用去重；持久化后的后续加载会去重。

## Decisions

### D1：固定使用 Coding Plan 的 Doubao Seed 2.0 Mini

标题仅需要从锚点、问题和首答中提炼主题。`doubao-seed-2.0-mini` 是 Coding Plan 已支持的轻量模型，足以完成此任务且成本低于现有可选的 2.0 Lite。复用现有 Coding Plan provider 和 `ARK_CODING_API_KEY`，确保流量继续走套餐专用端点。

备选方案是使用普通方舟按量端点或继续使用 MiniMax。前者会绕开项目既有套餐端点，后者正是本次配额失败来源，因此均不采用。

### D2：token 安全阀与标题长度策略分离

调用保留 48 输出 token 的成本安全阀，并将 AI SDK `maxRetries` 设为 0。输出 token 限制仅防止异常响应增加成本，不表达可见标题的字符或单词上限；提示词和清洗步骤都不再做长度截断。

备选方案是把标题固定为 16 个字符或英文单词数。它会在不同语言中产生不一致的可读性，并把展示职责错误放在服务端，因此不采用。

### D3：双层的一次性尝试记录

在每个分支上保存可选布尔标记，标题请求发出前原子设置该标记。它随整棵树 JSON 持久化，历史树缺少该字段时保持可生成的兼容行为。客户端同时把本标签页的 `treeId + threadId` 写入 `sessionStorage`，防止防抖持久化尚未完成时的刷新重新发起请求。

备选方案是只保留组件内 Set，或只保存模型成功的标题。两者都会让失败路径在刷新后重复调用，故不采用。

## Risks / Trade-offs

- [首次并发打开同一树的多个标签页] → 持久化前仍可能各自进行一次调用；持久化完成后所有后续加载均会跳过。
- [标题模型暂时不可用] → 自动标题不会在刷新后恢复重试；分支仍保留可读的默认锚点标题，避免可选功能反复消耗额度。
- [模型生成异常长短语] → 前端已有按容器宽度的省略规则，且调用的输出 token 安全阀限制异常成本。

## Migration Plan

1. 部署路由、模型常量及客户端防重逻辑。
2. 不执行数据库迁移；历史树的缺省尝试标记视为尚未尝试，并在首次符合条件时记录。
3. 如需回滚，可恢复 MiniMax 路由和旧标题策略；新增 JSON 字段会被旧代码忽略。
