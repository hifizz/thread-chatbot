## Context
后台壳、模型数据库、权限及参数管理的原设计保留。原实现将数据库读取扩散到业务判断，并让前端每 30 秒及聚焦时刷新；这超出了用户对配置生效及时性的需求。

## Revision Status
缓存与同步调用方案已实现，修订验收状态见 tasks.md。原版验收记录保留为历史证据，不单独代表本修订通过。

## Decisions
- `/admin/layout.tsx` 负责权限和公共壳；导航集中定义，业务页面与模型领域模块分离，复用 sidebar-08 Base UI。
- `model_catalog` 保存稳定内部 ID、启用、排序、版本和严格校验的配置 JSONB；全局设置保存默认模型，管理员成员与审计保持独立表。
- 后台读写仍直接使用数据库，保留管理员鉴权、同源校验、事务审计、版本冲突及默认模型保护。缓存只用于模型运行时配置，不缓存身份和授权结果。
- 运行时只由统一配置入口访问模型目录仓储；数据库是真实来源，业务函数不自行查询数据库，也不静默回退源码目录。
- 第一版通过 globalThis 让页面和接口的不同模块包共享每个服务实例的一份内存缓存，不引入 Redis、消息广播、全局隐式请求上下文或通用配置框架。

## Cache Lifecycle
- 缓存保存整份目录（含默认模型）及最后成功加载时间，成功加载后五分钟内为有效缓存。
- 无缓存时，入口等待数据库加载。并发冷启动读取共用同一个进行中的加载任务；失败则返回目录不可用，不使用空目录继续生成。
- 有效缓存直接返回，不查询数据库。
- 过期缓存立即返回旧对象，同时触发一次后台刷新。该实例已有刷新任务时，其他请求复用旧对象，不重复查库。
- 刷新成功且完整配置校验通过后整体替换缓存对象并更新时间；不得逐项修改旧对象。失败保留旧对象和成功时间，释放刷新任务，并在短暂重试间隔后由后续请求触发重试，避免故障期间每个请求都查库。
- 后台工作通过 Next.js after 托管，在响应结束后执行；受对应部署平台的请求时长及生命周期限制，不依赖无人托管的 Promise。
- 五分钟是请求触发刷新的阈值，不是全局同步时限。无请求时不主动刷新；多实例独立刷新、允许短暂版本差异，数据库故障时旧值可能保留更久。
- 管理员保存立即写数据库，后台可显示最新持久化结果，但不主动清空运行时缓存、不推送客户端更新。

## Request Boundary
接口或生成任务入口只加载一次配置，将完整配置或从中同步选出的模型对象显式传给命令、能力校验、附件编译和实际生成。后台管理的写入校验不使用这份可能过期的运行时缓存。

```ts
const config = await getModelConfig()
assertAllowedModel(config, modelId)
assertSupportsImages(config, modelId, attachments)
assertGenerationSettings(config, modelId, settings)
await generateReply(config, modelId, messages)
```

上述名称为契约示意。业务函数不能通过可选参数缺省分支再异步查库，不能在同一次处理的各步骤重新读取全局缓存。消息持久化、附件 I/O 和模型网络请求原有的异步行为保留；只收回配置判断引入的异步扩散。标题生成等独立任务也在自身入口取一次配置。

刷新整体替换缓存后，已经开始的处理仍持有旧配置，不会中途改变能力、路由或默认参数。用户未指定参数时使用该快照默认值；显式参数按该快照允许范围校验，不支持 effort 则不发送。

## Frontend Initialization
页面初始化时，将经过登录门禁的公开模型 DTO 与用户配置在同一次初始化响应/服务端页面数据中返回，不必将模型目录复制到每个用户的数据库记录中。前端配置容器只持有本次初始化快照，菜单及控件同步读取。

取消 30 秒轮询和聚焦刷新，不为模型目录单独增加页面加载请求。重新打开或完整刷新页面时重新初始化，但服务端可能先返回过期缓存，因此不保证刷新页面一次就必定取得数据库最新值。已移除仅供轮询使用的 `/api/models`，公开配置改随页面初始化返回。

旧页面仍可能显示已被服务端新缓存停用的模型，或保留已失效参数。服务端依据本次请求快照拒绝时，客户端应提示刷新并重新选择，不信任浏览器携带的能力声明；用户显式输入不得静默替换成另一模型。

## Change Scope
优先收回创建、发送、分叉、编辑、重试、更新 Thread 和内容解析中由配置查库引入的 async/await。显式传 config 可能仍要求这些文件变更，因此“7 个整文件撤回”“共约撤回 8 个、剩约 68 个文件”均为未验证估计，不承诺结果。保留动态配置所必需的路由、能力及默认值接入，不为减少文件数引入隐式依赖。

## Migration / Rollout
功能分支只改 schema，不生成 migration。在 develop 集成时统一生成并验证正式迁移，迁移后执行幂等 seed，再发布应用并授权已有管理员账号。未完成实现修订、对应验收及迁移门禁前 PR 继续为 draft。
