## ADDED Requirements

### Requirement: 独立后台框架
系统 SHALL 提供基于官方 shadcn sidebar-08 Base UI 源码的 `/admin` 公共布局，将导航、页头、用户菜单与业务页面分离。

#### Scenario: 后台入口
- **WHEN** 管理员访问 `/admin`
- **THEN** 进入 `/admin/models`，显示公共后台外壳和模型管理页面

#### Scenario: 添加后续页面
- **WHEN** 开发者添加用户分析或错误日志等后台功能
- **THEN** 通过独立路由和导航项接入，无需修改模型页面或聊天布局

#### Scenario: 小屏幕导航
- **WHEN** 管理员在手机上打开后台
- **THEN** 可通过侧边栏按钮打开导航抽屉，表格内容在自身区域滚动而不撑宽整页

### Requirement: 管理员授权
系统 SHALL 复用现有登录，在服务端分别校验后台页面数据读取和每个后台接口的管理员身份。管理员身份 SHALL 存储在数据库，不能由注册字段或客户端状态授予。

#### Scenario: 未登录访问
- **WHEN** 未登录用户访问后台页面或后台接口
- **THEN** 页面引导登录，接口返回 401，不泄露后台配置

#### Scenario: 普通用户调用接口
- **WHEN** 已登录的普通用户读取或提交后台模型配置
- **THEN** 接口返回 403，数据库保持不变

#### Scenario: 授权已有账号
- **WHEN** 部署维护者执行管理员授权脚本并指定已有用户邮箱
- **THEN** 该用户获得后台权限，重复执行不会创建重复成员；不存在的账号不会被自动注册

#### Scenario: 跨站提交
- **WHEN** 管理员写请求的 Origin 与实际访问域名不同，或请求不是 JSON
- **THEN** 拒绝请求，不修改模型配置

### Requirement: 持久化模型目录
系统 SHALL 在数据库保存稳定内部 ID、展示信息、上游 ID、已实现的请求兼容策略、能力、生成参数、启用状态和排序。网关地址和密钥 SHALL 保留在服务端环境变量中。

#### Scenario: 新增模型
- **WHEN** 管理员新增并启用现有兼容策略支持的中转模型，且中转服务已配置对应上游 ID
- **THEN** 无需发版；运行时缓存完成刷新且客户端重新初始化取得该模型后，可选择并请求该模型

#### Scenario: 复制配置
- **WHEN** 管理员复制已有模型
- **THEN** 打开带有原能力和参数的新增表单，内部 ID 留空，副本默认停用，保存后才产生新模型记录

#### Scenario: 稳定历史身份
- **WHEN** 管理员编辑或停用已有模型
- **THEN** 内部 ID 不变，历史对话及其模型标识不删除

#### Scenario: 新模型初始值
- **WHEN** 管理员打开空白新增表单
- **THEN** 模型默认停用，图片、工具及推理能力默认关闭，不发送 effort，输出默认值及上限为 16,000 token，管理员可以按实际模型支持调整

### Requirement: 能力与参数校验
系统 SHALL 分别配置图片输入、工具调用和推理能力，配置允许的 effort 档位及默认值，以及模型输出上限、可选输出档位和默认值，并在服务端严格校验。

#### Scenario: 无效默认值
- **WHEN** 默认 effort 不属于支持档位，或默认输出长度不属于可选档位，或可选输出长度超过模型上限
- **THEN** 拒绝保存并说明字段错误

#### Scenario: 兼容策略约束
- **WHEN** 配置包含未实现的策略、额外密钥或 URL 字段，或 effort 与所选兼容策略不兼容
- **THEN** 拒绝保存，不接受任意请求代码或任意网关地址

#### Scenario: 上下文限制
- **WHEN** 管理员填写上下文窗口
- **THEN** 模型输出上限不得超过该窗口；窗口未知时允许留空，不将推测的显示标签作为已验证限制

#### Scenario: 使用默认参数
- **WHEN** 用户未显式选择生成参数
- **THEN** 新生成使用该模型的默认输出长度及默认 effort

#### Scenario: 不支持 effort
- **WHEN** 请求没有配置 effort 档位的模型
- **THEN** 不发送 effort 参数，仍使用该模型输出默认值

#### Scenario: 用户自选参数
- **WHEN** 用户显式提交生成参数
- **THEN** 服务端同步检查其属于本次请求配置快照的允许范围；客户端切换模型时将不兼容偏好回退为新模型兼容的默认值

#### Scenario: 不支持图片
- **WHEN** 用户为不支持图片输入的模型提交新增图片附件
- **THEN** 在发起模型请求前拒绝该输入；文本及文档提取沿用现有附件流程

#### Scenario: 不支持工具
- **WHEN** 生成模型关闭工具能力
- **THEN** 不启用搜索或 Artifact 工具，不向上游发送工具声明和工具选择参数

### Requirement: 目录发布与公开数据
系统 SHALL 在页面初始化时随用户配置返回公开模型目录，由前端配置容器同步提供给菜单和能力控件。普通客户端 SHALL 仅收到公开模型信息、能力与默认参数，不包含管理员配置。

#### Scenario: 页面初始化
- **WHEN** 用户打开或完整刷新聊天页面
- **THEN** 同一次页面初始化返回用户配置及来自服务端配置入口的公开模型快照，不要求前端另发模型目录请求

#### Scenario: 保留已打开页面配置
- **WHEN** 后台修改模型、页面重新聚焦或经过刷新周期
- **THEN** 已打开页面保持初始化快照，不轮询、不因聚焦自动更新

#### Scenario: 旧页面配置失效
- **WHEN** 旧页面提交的模型或参数不被服务端本次请求快照允许
- **THEN** 服务端拒绝，客户端提示刷新并重新选择，不静默切换模型；重新初始化也可能取得旧缓存，不保证一次刷新立即获得数据库最新值

#### Scenario: 敏感字段隔离
- **WHEN** 已登录普通用户接收页面初始化模型配置
- **THEN** 响应不包含上游 ID、请求兼容策略、密钥或后台审计记录

#### Scenario: 未初始化目录
- **WHEN** 服务端无可用缓存且数据库目录尚未初始化
- **THEN** 服务报告目录不可用，不静默使用源码模型列表继续生成

### Requirement: 配置一致性与审计
系统 SHALL 使用版本冲突检测防止覆盖更新，将配置变更和审计记录原子提交，并在生成开始时固定配置快照。

#### Scenario: 并发编辑
- **WHEN** 管理员保存过期的模型版本或默认模型设置版本
- **THEN** 返回 409，不覆盖新版本，不写入成功变更审计

#### Scenario: 默认模型保护
- **WHEN** 管理员将模型设为默认或尝试停用当前默认模型
- **THEN** 只有启用模型可设为默认；当前默认模型必须先被其他默认模型替换才能停用

#### Scenario: 审计变更
- **WHEN** 模型配置或默认模型修改成功
- **THEN** 在同一事务保存操作者、修改目标、修改前后数据和时间

#### Scenario: 生成期间修改
- **WHEN** 管理员在一个生成已经获取配置快照后修改或停用模型
- **THEN** 该生成继续使用已获取的能力、上游路由和参数快照，之后的新生成在入口获取当时的缓存快照；缓存尚未刷新时允许继续使用旧配置，刷新后使用新配置或拒绝已停用模型

### Requirement: 初始化与发布门禁
系统 SHALL 提供不覆盖已有模型编辑的幂等初始化。正式迁移 SHALL 遵循仓库 develop 集成流程，未生成并验证迁移前不得视为可发布。

#### Scenario: 重复初始化
- **WHEN** 再次执行模型目录初始化脚本
- **THEN** 仅补充缺失模型及缺失全局设置，不覆盖管理员已经编辑的配置或默认模型

#### Scenario: 正式发布
- **WHEN** 准备部署依赖新表的应用版本
- **THEN** 必须先由 develop 集成任务生成并验证正式 migration，应用迁移并初始化目录，再发布应用和授权管理员

#### Scenario: 验收边界
- **WHEN** 报告本地验收结果
- **THEN** 分别说明 PGlite 数据库、模拟上游和浏览器的测试证据，不将其描述为正式 PostgreSQL 迁移、真实供应商调用或生产部署已通过

### Requirement: 统一配置缓存
系统 SHALL 将模型运行时查库集中在统一入口，使用每实例五分钟缓存；过期先返回旧值并后台刷新，后台保存不主动使缓存失效。管理员身份校验和后台读写 SHALL 不受该缓存影响。

#### Scenario: 冷启动
- **WHEN** 实例没有缓存且请求配置
- **THEN** 等待数据库加载，并发请求共用一个加载任务；失败返回目录不可用

#### Scenario: 缓存有效
- **WHEN** 距最后成功加载不足五分钟
- **THEN** 直接返回缓存，不查数据库

#### Scenario: 缓存过期
- **WHEN** 距最后成功加载已满五分钟且收到配置请求
- **THEN** 不等待数据库，先返回旧缓存，并用运行时支持的后台生命周期触发刷新；已有刷新任务时不重复启动

#### Scenario: 刷新成功
- **WHEN** 新目录完整读取并通过校验
- **THEN** 整体替换缓存对象并重置有效期，不修改已交给请求的旧对象

#### Scenario: 刷新失败
- **WHEN** 后台读取或校验失败
- **THEN** 保留旧缓存及最后成功时间，释放进行中任务，在短暂重试间隔后由后续请求重试，不让每个请求立即重复查库

#### Scenario: 延迟生效边界
- **WHEN** 管理员保存模型启停或默认参数
- **THEN** 数据库立即持久化，各实例按请求触发刷新逐步生效，不推送更新；五分钟不代表无请求、多实例或数据库故障时的全局生效上限

### Requirement: 入口加载与同步业务判断
系统 SHALL 在每个请求或独立生成任务入口加载一次配置并显式传递，模型可用性、图片能力和生成参数判断 SHALL 同步执行，不自行读库或重新取全局缓存。

#### Scenario: 同一处理链使用同一份配置
- **WHEN** 入口取得配置并开始业务处理
- **THEN** 命令判断、附件编译和实际生成使用同一快照，即使后台刷新完成也不切换配置

#### Scenario: 减少异步扩散
- **WHEN** 调整调用方接入统一入口
- **THEN** 去掉配置判断引入的 async/await，但保留真实 I/O 的异步；允许显式 config 参数所需的文件修改，不承诺整文件撤回或固定文件减少数量
