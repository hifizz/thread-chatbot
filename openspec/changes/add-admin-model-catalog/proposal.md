## Why
模型目录、能力及生成默认参数目前固定在源码中，新增中转模型需要重新发版。需要独立可扩展的后台框架，以及数据库驱动的统一模型目录。

## Revision Status
五分钟缓存、入口显式传参和同步业务校验已应用到代码。修订验收状态见 tasks.md；正式 migration 仍属于 develop 发布门禁。

## What Changes
- 基于 shadcn sidebar-08 Base UI 官方源码建立 /admin 公共布局，模型管理独立在 /admin/models。
- 数据库保存模型配置、默认模型、管理员身份和修改记录；复用现有登录，每个后台接口独立校验管理员。
- 支持新增、复制、编辑、排序、启停模型，配置图片、工具、推理、effort、输出预算和已实现的协议适配。
- 模型运行时读取集中到统一配置入口：五分钟缓存，过期先返回旧值并后台刷新，冷启动无缓存时等待加载。
- 请求入口加载一次并显式传递配置；模型可用性、图片能力及生成参数判断保持同步，一次请求固定使用同一份配置。
- 前端在页面初始化时随用户配置一并接收公开模型目录，保持当前页面快照，不轮询、不因聚焦刷新。
- 后台保存仅更新数据库，不主动使运行时缓存失效或推送到已打开页面；允许模型启停和默认值延迟生效。
- 提供幂等初始化与管理员授权脚本；功能分支不生成 migration。

## Capabilities
### New Capabilities
- `admin-model-catalog`: 可扩展后台和动态模型目录。

## Impact
涉及模型域、认证授权、数据库结构、聊天输入框与流式请求。密钥仍由服务端环境变量管理。新协议仍需代码适配。上线必须在 develop 生成并验证迁移，再初始化目录和管理员。

## Scope Estimate
先前“约撤回 8 个文件、PR 收敛到约 68 个文件”仅为初步估计，不是承诺或验收指标。显式传递 config 仍可能要求调用方修改参数，因此原先只增加 async/await 的 7 个文件也不保证整文件撤回。以消除分散查库、保持业务判断同步为目标，实际数量在实施后的 diff 中确认。
