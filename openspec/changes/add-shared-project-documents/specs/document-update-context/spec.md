## ADDED Requirements

### Requirement: 项目文档与历史产物阅读入口区分

项目文档视图 SHALL 按 Document 展示一份持续文件，默认读取当前版本；历史 Message Artifact、Quote 与 Fork 来源 SHALL 固定历史内容。用户可通过文档标题旁的版本 Dropdown 显式切换查看最新版、历史版本和差异；历史版本展示“正在查看历史版本”与“查看最新版本”，切换只改变阅读内容，不执行回滚。活动选区或问题草稿 MUST NOT 因后台 head 更新被自动重新绑定。

#### Scenario: 最新版到达时正在划选
- **WHEN** 用户正在 R1 划选并输入问题，此时 R2 提交
- **THEN** 当前选区仍绑定 R1 Artifact，显示可查看新版本的提示，不能将旧 Anchor 套到 R2

#### Scenario: 查看差异
- **WHEN** 用户选择 R1 与 R2 的差异
- **THEN** 由固定版本内容计算只读差异，展示来源和修改说明，不触发写入

### Requirement: 文档各版本分叉遵守实际来源

文档版本中的划选 SHALL 使用该版本实际 Artifact ID，并沿用 #143 的来源 Message、父 Thread、Anchor 和 Quote 合同。Document 创建者所在 Thread 不替代具体版本的来源。普通新 Fork 的 completed 和有效时间线规则保持不变。

#### Scenario: 在分支更新后的版本划选
- **WHEN** R2 的 Artifact 由 Thread A 的 Message 产生，用户在 R2 划选开分支
- **THEN** 新分支挂在 A 下并固定 R2 Artifact，而不是因为 D1 起源于主线就挂回主线

#### Scenario: 更新已提交但回复未完成
- **WHEN** R2 已提交，而来源 Message 仍在生成或最终停止/失败
- **THEN** 文档可以读取和继续更新；新建分支入口按 #143 的 completed 要求明确不可用，不伪造消息完成状态

#### Scenario: 删除引用块
- **WHEN** 用户删除版本选区的 Quote
- **THEN** 不从 Document、Revision 或 Thread Anchor 恢复隐藏引用，正常历史与用户显式读取保持

### Requirement: 主线展示已提交文档进展

主线 SHALL 从不可变 Revision 记录展示各文档已提交版本变化、修改说明和来源 Thread。只有真实提交才计为进展，失败/unchanged 不新增修改事件。界面可见、用户浏览和模型接收 SHALL 作为不同状态处理，不以打开面板表示模型已读。

#### Scenario: 多分支完成更新
- **WHEN** A/B/C 分别成功产生同一文档 R2/R3/R4
- **THEN** 主线能查看这三次提交及来源，以文档版本链表达先后，当前文档展示 R4

#### Scenario: 用户只查看进展
- **WHEN** 用户打开主线进展面板但没有发起新对话
- **THEN** 不自动修改历史消息、不运行模型、不把这些版本标记为模型已接收

### Requirement: 主线下一轮固定接收版本清单

服务端 SHALL 在接受主线下一条用户消息时，使用一致的已提交数据库快照确定新增/改变文档及尚未接收的提交说明，保存服务端生成的固定上下文 Part，记录 schemaVersion、Document/Revision/Artifact ID 和提交 ID。用户选择本轮文档范围时按该可见范围固定；无范围选择时接收所有改变文档。不得信任客户端自报权威版本/说明或以可变全项目已读标志替代真实消息记录。

固定清单先表示计划输入；系统 SHALL 在通过预算并实际发出模型请求时保存使用收据，只有固定清单与使用收据共同成立才推进接收位置。生成前失败不得标记模型已接收；使用收据不代表模型理解或认同文档内容。

#### Scenario: 新用户消息接收 R2
- **WHEN** 主线接受用户消息时 D1 当前为 R2
- **THEN** 该消息固定 R2 及相关提交记录，之后 R3 提交也不修改本轮清单

#### Scenario: 多文档同时变化
- **WHEN** 接受消息期间 D1/D2 均可能被其他 Thread 修改
- **THEN** 清单来自一个一致数据库快照，每个条目明确固定版本，不按异步 UI 展示猜测当前内容

#### Scenario: 本轮只选择部分文档
- **WHEN** 用户在可见进展入口选择 D1 作为本轮范围
- **THEN** 只接收 D1，D2 更新仍待接收，不能推进 D2 的模型接收位置

#### Scenario: 保存清单后尚未调用模型就失败
- **WHEN** 清单已随新用户消息保存，但预算或生成前校验失败
- **THEN** 不产生请求使用收据，这些更新仍待接收，下一轮不能因存在消息 Part 就跳过

### Requirement: 最终模型上下文按固定版本展开

编译器 SHALL 在新用户消息的固定位置展开所接收文档的完整内容与变更说明，去重以实际完整 Artifact 身份和内容为准。重试/重生必须复用同一已保存清单；显式读取新版以新的固定工具结果记录。MUST NOT 重新解释旧 @artifact 为最新版本、重写旧消息或更改 forkContext。

#### Scenario: 正在使用 R2 时出现 R3
- **WHEN** 主线请求已固定 R2，而分支提交 R3
- **THEN** 本轮继续依据 R2；只有之后新消息或显式新工具读取才引入 R3，并保存其版本身份

#### Scenario: R1 已在历史中
- **WHEN** 历史含 R1，而本轮接收 R2
- **THEN** 不按相同 Document ID 跳过 R2，全量提供 R2 或按相同 Artifact 已完整包含规则去重

#### Scenario: 只传摘要或工具 ID
- **WHEN** 中间结果仅有标题、ID 或修改说明
- **THEN** 不判定文档全文已进入模型，最终编译仍读取被固定的完整内容

#### Scenario: 重试同一消息
- **WHEN** 相同用户消息重试或重新生成，此时项目已有更多提交
- **THEN** 复用原文档清单和确定性输入，不静默把新 head 注入历史请求

### Requirement: 上下文预算与子分支隔离

系统 SHALL 将版本全文、历史、工具结果和说明计入统一最终请求预算，不静默截断、压缩或忽略更新。已知超限在付费模型调用前明确失败；未知计量保留 unknown 并提供可读的提供商错误。子 Thread 仅接收正常继承、实际引用和显式读取，不自动加载所有兄弟讨论。

#### Scenario: 主线进展过多
- **WHEN** 默认接收范围使完整请求已知超限
- **THEN** 明确提示用户缩小本轮文档范围，不伪称未进入请求的更新已被模型接收，不改写旧历史

#### Scenario: 子分支继续对话
- **WHEN** Thread A 继续讨论 D1，Thread B 更新无关 D2
- **THEN** 不因 Project 有新版本自动注入 B 的讨论或 D2 全文，A 可按用户要求显式读取

### Requirement: 组件与工具状态以权威 DTO 为准

界面 SHALL 复用 #143 的阅读、划选、来源导航及现有组件，分离文档列表、版本阅读、历史/差异、工具状态和主线进展。组件不得自行 patch 正文或决定数据库写入资格。提交成功、冲突处理、未提交失败和已满足状态必须清楚区分，手机版复用现有 Drawer 与焦点规则。

#### Scenario: 显示提交结果
- **WHEN** 服务端返回 committed
- **THEN** 展示本次 Revision、修改说明、差异入口与来源；不是直接把本地预览当作保存后的正文

#### Scenario: 停止后的已提交操作
- **WHEN** 工具已提交但整条回复被停止
- **THEN** 卡片仍显示已提交的版本事实，不能显示为未修改或自动恢复旧版

#### Scenario: 桌面与手机查看同一历史
- **WHEN** 用户切换设备打开 R2
- **THEN** 使用同一固定 DTO 内容与来源，布局变化不改变引用语义或提交状态

### Requirement: 失败计划与实际历史区分

系统 SHALL 保留失败轮次的固定清单记录。后续新用户消息不得自动展开此前无使用收据的计划全文；原用户正文及已使用历史必须保持。重试原消息仍展开该轮原清单。提供商仅返回初始化或上下文错误时不得记录已接收。

#### Scenario: 缩小范围后重新提交
- **WHEN** 上一轮因上下文超限未收到有效响应，用户缩小范围发送新消息
- **THEN** 本轮只展开新清单和此前已使用的历史，不偷偷补发上一轮未使用的文档全文

#### Scenario: 导出和系统文件分享
- **WHEN** 用户阅读 V1 并导出或通过系统分享 Markdown 文件，而文档 head 为 V3
- **THEN** 文件仅包含 V1 固定正文；不支持系统文件分享时提示导出，不创建浮动版本链接

### Requirement: 当前文档目录与固定历史引用分离

新建引用候选、项目文档列表及文档数量 SHALL 使用统一的当前文档目录，每个 Document 只展示当前内容。消费者 MUST NOT 分别实现版本排序或按标题合并。按 Document ID 读取且未指定历史版本时 SHALL 返回当前内容；历史引用仍按固定 Artifact ID 读取。已知当前正文尚未载入时 MUST NOT 将旧内容冒充当前内容；来源资格检查不得导致回退到旧版。

#### Scenario: 一份文档更新三次后的新引用
- **WHEN** 项目包含同一 Document 的多个固定版本
- **THEN** 新建 @ 引用仅出现一份文档，选择后引用当前固定内容，旧消息中的引用仍保留原文

#### Scenario: 两份独立文档同名
- **WHEN** 两个不同 Document 使用相同标题
- **THEN** 目录仍保留两份独立文档，不以标题去重
