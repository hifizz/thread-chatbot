## Context

`/` 已是公开落地页，但当前以多个产品模拟图、纸张网格和手绘细节组成，与 Thread Chat 工作台的暖黄纸面、黑色文字、绿色强调色不一致，也没有一段连续叙事解释分支对话的价值。现有首页的内容已集中在 `constants/landing.ts`，页面由 `components/landing/*` 组合，适合在不影响 `/thread-chat` 业务的前提下整体替换。

用户将提供 Hero MP4；实现必须先提供稳定的空壳和静态缺省状态。

## Goals / Non-Goals

**Goals:**

- 用视频驱动的编辑式叙事，在首页清楚说明 Thread Chat 的产品定位和差异。
- 复用 `/thread-chat` 的现有主题 token：暖黄背景、黑色文本、绿色互动。
- 在桌面及移动端保持视频、文字层级和 CTA 的可读与可操作性。
- 将全部首页文案、链接和视频路径集中在 landing 常量中。

**Non-Goals:**

- 制作或编辑最终 MP4、接入视频托管、分析或 CMS。
- 改动 `/thread-chat` 的工作台、认证、数据模型或 API。
- 在本次实现额外引入动画库或设计系统依赖。

## Decisions

### D1：采用“视频证据 → 编辑文稿”结构

首页按导航、视频 Hero、产品声明、Why I built、Why not existing chat、CTA、页脚排列。视频先展示真实产品，接下来的窄文本列解释判断，避免旧首页并列展示多个功能模拟图造成的认知分散。

替代方案是保留功能网格并只修改颜色；不采用，因为它无法满足“完全不要当前首页 UI 风格”的约束。

### D2：落地页复用 thread-chat 颜色与字体 token

Landing scope 使用 `#f5f2ea`、`#24211b`、`#6a6357`、`#e2dccd` 和 `#2f7d6b`，并采用与 thread-chat 相同的 UI 无衬线字体栈。绿色只承担 CTA、链接状态、焦点和少量强调，不做大面积背景。

替代方案是延续当前首页独立的橙、蓝、紫与手绘标记；不采用，因为会削弱首页与产品工作台的连续性。

### D3：Hero 视频是渐进增强，不是页面依赖

`VideoHero` 使用固定 `aspect-ratio: 16 / 9` 容器并覆盖左下 slogan。视频配置 `muted`、`loop`、`playsInline` 和 `preload="metadata"`；静态占位和文本始终先渲染。视频资源缺失、加载失败或用户偏好减少动态效果时，保留占位与可读文本，不显示失效控件。

替代方案是使用远程视频平台或把视频设为必需资源；不采用，以避免外部依赖、首屏失败和后续替换成本。

### D4：内容与展示继续分离

`constants/landing.ts` 持有首页文案、CTA、法务链接和可替换视频路径。`app/page.tsx` 仅负责按序组合 section；新/重写的 landing 组件与 CSS 只负责展示。开始聊天 CTA 使用现有路由常量，避免重造跳转或认证逻辑。

### D5：响应式以阅读顺序为优先级

桌面使用最大 1180px 的视频区域和约 700px 的文稿列；窄屏收至 20px 边距、保留单一导航 CTA、视频全宽且所有段落按文稿顺序堆叠。CTA 在小屏为全宽触控目标。内容不依赖 hover 才能理解。

## Risks / Trade-offs

- **[最终视频尚未到位]** → 静态同尺寸占位与 slogan 作为正式空状态，后续只替换常量路径和资源文件。
- **[自动播放在部分设备受限]** → 视频静音且内联；不能播放时页面不依赖播放结果。
- **[“为什么不是 ChatGPT/Codex”的表述可能过度泛化]** → 文案只陈述本产品可验证的结构差异，不评价对方整体能力。
- **[首页整体重写可能遗漏旧 section 引用]** → 用 TypeScript 检查、生产构建和针对 `/` 的桌面/移动验证覆盖。

## Migration Plan

1. 更新 landing 常量与组件组合，重写 landing scope 样式，移除不再使用的旧首页 section 和类型。
2. 将 Hero 先接入本地占位路径；用户提供 MP4 后仅添加 `public/` 资源并更新常量。
3. 运行 `pnpm typecheck`、`pnpm lint`、`pnpm build`，再在桌面和 375px 宽度检查关键布局与可访问性。
4. 回滚时恢复此前 landing 组件、常量和样式提交；不涉及数据库或外部迁移。

## Open Questions

- 最终 MP4 的文件名和内容由用户提供；实现使用明确的临时资源路径和可替换常量，不阻塞开发。
