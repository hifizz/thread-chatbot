## Why

轻量搜索快照足以回答许多最新信息问题，但复杂编程文档、迁移指南和长页面常需要读取原文上下文。直接把任意 URL 暴露给模型会引入 SSRF、重定向绕过、提示注入、上下文爆炸和费用失控，因此深读必须建立在搜索产生的受控来源账本上。

## What Changes

- 在 `add-proactive-web-search` 通过验收后，为同一轮模型工具循环增加 `readSource({ sourceId })`，不提供 `readUrl({ url })`。
- 搜索结果进入服务端来源账本并获得不可伪造的 `sourceId`；模型只能深读本轮已验证的搜索结果，不能提交任意 URL。
- 通过托管提取 provider 获取正文，并在应用层执行协议、目标、重定向、内容类型、超时、大小、字符数和单轮调用上限校验；MVP 后续阶段仍不运行浏览器。
- 将网页正文视为不可信数据，显式隔离页面指令与系统/用户指令；页面要求泄露密钥、改变工具策略或访问其他地址时必须忽略。
- 生成结构化引用账本，把回答中的事实主张映射到实际使用的来源；模型在最小可支撑的实体、事实句或段落后输出 sourceId 引用标记，UI 将其渲染为可点击、可核验、可持久化的信息源 tag，点击后用安全的新 tab 打开原始来源。
- 记录提取调用的 provider 成本、正文大小、延迟、失败类型和引用使用情况，并沿用微元计费与单轮预算。
- 保留无深读降级：提取失败、来源不安全或预算耗尽时，模型只能使用已取得的搜索快照并披露限制。

## Capabilities

### New Capabilities

- `controlled-web-fetch`：基于来源账本的受控网页深读、输入/输出安全边界、预算和失败降级。
- `grounded-web-citations`：来源账本、实体/主张/段落级信息源 tag、事实到来源的可核验映射、安全新 tab 跳转与持久化展示。

### Modified Capabilities

（无——本 change 依赖 `add-proactive-web-search`，但以新增能力扩展它，不修改当前 canonical specs。）

## Impact

- **依赖**：必须先完成并验收 `add-proactive-web-search`；没有来源账本时不得启用深读工具。
- **搜索/抓取层**：`lib/ai/search.ts`、搜索工具模块和 `app/api/chat/route.ts` 增加请求内来源注册表与提取预算。
- **消息与 UI**：Thread Chat 流消费器、领域消息结构、树持久化和 Markdown 渲染增加结构化来源数据；旧消息保持兼容。
- **安全**：新增 URL/重定向/内容校验、提示注入隔离、超时与正文大小限制；不允许私网、环回、link-local 或非 HTTP(S) 目标。
- **计费**：新增 extract/fetch 类型的外部用量流水与用户费用展示。
