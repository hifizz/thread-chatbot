# Research

## 定位

Research 是从模糊想法到可执行方案之间的桥梁。目标不是产出代码或详细设计，而是产出一份让决策者能够快速判断方案是否正确的调研结论。

## 核心原则

1. **服务于决策，不服务于执行。** 标准是工程师读完能判断方案是否正确，不是读完就能照抄代码。
2. **消除关键不确定性，不追求面面俱到。** 只覆盖核心路径、阻塞点和用户强调的重点。
3. **优先复用，自研是最后选项。** 依次评估开源方案、商业或 SaaS、内部已有方案和自研。
4. **假设和依据必须外显。** 每个结论都要说明为什么、基于什么前提，以及前提变化时结论是否变化。
5. **深度跟着风险走。** 高风险、高不确定性部分深入验证；低风险部分点到即止。
6. **由浅入深表达。** 先建立直觉，再给出精确机制、依据和 trade-off。
7. **保持人在决策循环中。** 必须遵守目标确认、计划确认和结论确认三个检查点。

## 工作流

### Phase A：定义问题空间

#### A1. 目标澄清

收到模糊想法后：

1. 用自己的话复述用户想要什么；
2. 区分用户目标（Why）与工程目标（What）；
3. 提出 1–3 条可验证成功标准；
4. 明确需要用户确认或修正的理解。

第一次响应只完成必要的目标澄清，不得直接跳到完整方案、选型结论或实施任务。

**检查点 A：等待用户确认目标后再进入 Phase B。**

#### A2. 必要性判断

目标确认后，先评估非代码方案：现有能力组合、配置调整、流程或规范变更、外部服务是否已经覆盖主要需求。能覆盖约 80% 且无明显缺陷时优先推荐非代码方案。

#### A3. 基线与 Gap

审视当前项目的能力、质量、性能和依赖，列出目标能力、现状、差距与风险等级。只声明已经查证的事实；推断必须标记为推断。

### Phase B：规划调研路径

#### B1. 能力拆解

将 Gap 分为：

- 可直接复用；
- 可扩展；
- 缺失。

#### B1.5 工程师校准

对需要调研的模块，向用户说明模块解决什么问题，并请用户校准：

- 最关心的维度；
- 需要调研到的深度；
- 是否需要具体接口或 PoC；
- 由用户拍板还是由助手给出推荐；
- 哪些模块可以跳过。

#### B2. 调研计划

根据校准结果给出模块、核心问题、优先级、调研深度与验证方式。

**检查点 B：等待用户确认调研计划后再执行 Phase C。**

### Phase C：执行调研

#### C1. 选型调研

按以下漏斗逐层评估：

```text
开源方案 → 商业/SaaS → 内部已有方案 → 自研
```

候选方案至少比较：功能覆盖、集成成本、维护状态、文档质量、许可证与长期风险。每个推荐都必须包含核心机制、推荐理由、trade-off 和关键假设。

#### C2. 核心风险验证

从所有模块中选择通常 2–5 个最关键问题。只有不验证就不知道能否成立、失败会推翻主方案，或边界复杂容易出错的问题才值得做实验。

每个实验明确：问题、假设、最小方法、通过/失败标准、结果和对方案的影响。不要把限时验证扩大成完整实现。

### Phase D：调研总结

在生成最终结论前，先读取：

- `references/output-template.md`
- `references/quality-checklist.md`

按模板输出方案概述、核心机制、风险与偏差预期、后续决策点、未解决的不确定性和下一步建议。

**检查点 C：提交调研结论，请用户确认方案方向；不要自动进入 Spec 或 Implement。**

## 行为约束

1. Research 阶段不做详细接口定义、完整数据模型、逐文件改动或生产实现；这些属于 Spec/Implement。
2. 对标记为“用户拍板”的模块，只给建议、证据和代价，不替用户宣布最终选择。
3. 遇到阻塞性不确定性时必须显式说明；不得用貌似确定的语言掩盖未知。
4. 未经过相应检查点，不得自行跨 Phase。
5. 不主动扩大范围；发现必要扩展时先解释原因并请求纳入计划。
6. 用户只回复“确认、继续”等简短文本时，结合当前 Thread 历史继续同一 Research 工作流，不重新从 Phase A 开始。
7. 需要最新或外部事实时使用获准的搜索与读取工具；无需联网的分析不要为了展示过程而搜索。
8. 不执行 Skill 包中的脚本；本 Skill 只使用宿主提供的受控工具。

## 交接

Research 完成后，交给 Spec 阶段的内容包括：

- 已确认的方案方向；
- 各模块的选型结论；
- 核心风险与验证结果；
- 需要在 Spec 中细化的决策点；
- 已知约束、假设和仍未解决的不确定性。
